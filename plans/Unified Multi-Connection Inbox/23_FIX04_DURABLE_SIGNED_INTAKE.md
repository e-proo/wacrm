# FIX-04 — Durable signed OpenWA intake (TEST only)

## Contract
One existing webhook receipt ledger is the durable queue; one existing CRM business pipeline handles both synchronous and queued intake. Verify HMAC, replay window, session/instance and credential binding before atomic enqueue. A 202 is acceptance of persisted encrypted evidence, not proof of CRM processing or WhatsApp delivery. Exact duplicate identity returns queued; conflicting digest is rejected. Payload and binding use existing AES-GCM encryption; do not log ciphertext, secrets or raw payload. The raw body is bounded to below 24 MiB and per-account retained evidence to 500 records/128 MiB. Upstream/PostgREST/proxy limits may be smaller: reject without a false acceptance.

Pending jobs survive restart. The worker claims one event at a time, with per-connection ordering and immutable lease ownership. An expired or uncertain started job is held for review rather than replayed; a successfully finalized receipt is reconciled without duplicate business processing. An unresolved review blocks later events for the route. An administrator may explicitly close it unverified during maintenance after stopping all relevant workers; this does not assert delivery, rerun work or delete evidence.

The existing LID/ACK deferred path is retained. New handoffs pin the canonical/legacy mode and preserve encrypted original evidence for unresolved identity/inline media until successful completion or review. Older unpinned jobs retain their legacy contract. Irreversible deferred business work is not automatically reclaimed after starting. Canonical review evidence is retained. There is no automatic purge of uncertain/closed evidence: a retention and capacity decision is required before GA. This is not an external exactly-once guarantee.

## Deployment and acceptance fence
Leave WACRM_OPENWA_DURABLE_INTAKE off until migration, CI and explicit controlled acceptance are approved. TEST-only gate: WACRM_OPENWA_DURABLE_INTAKE=test_only. Keep WACRM_INBOX_CANONICAL_INGRESS and inbox actions off until FIX-05 and verified enrollment/primary/namespace proof. Never switch modes or roll back binaries while accepted jobs or deferred handoffs remain unresolved; stop intake and drain/reconcile using the original mode. Old synchronous handlers cannot seize new durable receipts. Preserve ENCRYPTION_KEY across deployment and restart.

On Windows npm run dev uses an independent intake poll (5s) when the durable gate and WACRM_DEV_OPENWA_INTAKE_WORKER=on are active. npm run dev:next does not start automatic workers. The self-host TEST scheduler polls every 15s; use one authorized scheduler authority, not Windows and host simultaneously. Explicitly disable unrelated send workers (WACRM_DEV_AGENT_TASK_WORKER=off and WACRM_DEV_BROADCAST_WORKER=off) and review all inbound automation/agent/send policy and exact owned test targets before enabling live intake: inbound processing itself can dispatch effects. No live send is authorized by implementation or a worker tick.

## Monitoring and verification
Admin Inbox > OpenWA intake monitoring shows state counts, queue age, mode/review blocks, unfinished old receipts, retained bytes, and bounded 24h latency sample. HTTP Server-Timing measures intake only, not processing/delivery. The panel is not a worker heartbeat. Separate canonical identity reviews remain in FIX-03. Before live acceptance verify HMAC failure, duplicate/conflict, DB outage, queue persistence/restart, worker lease fencing, concurrent claims, route/credential changes, ACK/LID handoffs, inline/archive media and normal Meta regression. Measure actual Cloudflare/provider timeout and end-to-end text/image/video/document latency on owned TEST numbers. Inspect actual gateway version/config, verify zero unresolved backlog or explicitly disposition with evidence, and check NOTE-001 security debt. No production rollout or live acceptance claimed.

Existing eight unfinished synchronous OpenWA receipts have no durable original payload; do not replay, mark delivered or automatically close them. Existing two canonical namespace reviews lack proof; retain them, do not manufacture evidence. Record final CI and TEST smoke evidence in Linear.
