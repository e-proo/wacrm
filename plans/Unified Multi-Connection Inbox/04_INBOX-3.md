# INBOX-3 — Provider-aware policy and safe actions (SOF-71)
Depends INBOX-2; critical correctness gate before enabling new Inbox sending.
## 3.1 Capabilities and policy
- Server returns effective provider, connection, readiness, may_send_text/media/template/interactive/reply/reaction/read, blocked reason, Meta last_inbound_at and window_expires_at from authoritative same-connection customer message, not last CRM-wide message or client clock. Compute exact timestamp comparison, timer updates in UI; no known inbound => closed window; unknown context => fail closed. Enforce immediately before send on server; don't weaken Meta rules. OpenWA window not applicable; text/media allowed only when adapter capabilities, role, verified recipient, ready and guardrails permit; preserve activation/consent/Pilot, caps, manual pause, circuit breaker and audit.
- Hide Meta template/interactive/reaction UI on OpenWA where unsupported; use supported text quick replies, media types/limits derived from capability. Draft preview, async send and stale state recheck all gate decisions; no false error 'expired' for OpenWA.
### 3.2 Explicit sender and actions
- New Inbox send request conveys thread ID/connection ID + stable idempotency key; server authenticates tenant/role, validates thread membership and exact provider, resolves existing transport (not another send pipeline). Reject mismatched parent/provider/connection, stale/unready/archived, unknown legacy, unauthorized recipient, no implicit default. Meta explicit selection supported safely; preserve legacy contact/API default contracts. Same-phone OpenWA recovery only explicit authorized, verified identity, visible destination; history remains unchanged. New thread/outbound-only path with connection selected explicitly; no LID to phone inference; no new contact send unless authorized.
- Text, media, reply, template, interactive and reactions use exact same context. Retry only proven pre-dispatch fail with explicit operator action and policy recheck; stable key for repeated browser request, pending ambiguous UI with safe reconciliation link; distinguish failed vs unknown. No upload deletion if provider may have accepted. Don't duplicate messages on ACK/echo/reconnect.
- Read route verifies thread, exact verified native JID of connection, no cross-session mark, no provider calls for wrong/unknown; WACRM read vs provider read state separate; preserve roles and admin-only check. Mark/reaction/reply to legacy null only when independently proven and authorized.
### 3.3 Integration compatibility
- Audit router default/latest inbound call sites: AI context/drafting/autoreply, flows, automation, tasks, broadcast reply attribution, notifications/CRM. Preserve existing business workflow IDs and explicit task/broadcast bindings; propagate causal connection on inbound-triggered sends where necessary, scope prompt history/notification read to intended thread without mixing business facts or tenant. Don't alter task/broadcast worker approvals/caps or queued reservations. Tests for mixed inbound while work in flight and no silent failover; any business semantic change needs ADR and dedicated tests.
## DoD
Meta: window open, expired/no inbound, exact boundary, new inbound same connection and unrelated OpenWA inbound. OpenWA: old/no recent inbound when approved and ready, paused/pilot/cap/restricted negatives, no template/interactive/reaction, correct media/reply/read. Both: duplicate key, ambiguous network outcome, connection switch before send, cross-account/role, cross-thread reply and archived/recreated. CI+TEST mocks/transaction verified; provider live deferred to INBOX-6. Flag on only after security/acceptance gates.
