# ADR-INBOX-001 — Connection-scoped operational projection
Date 2026-11-21 | Technical decision: ACCEPTED for design, not activation | SOF-82 | Baseline 0fd459f. 
## Decision
Choose a durable additive projection `inbox_threads` over an aggregate read view or physically splitting CRM conversations. TEST 19 nonempty parent rows produce 32 exact connection pairs, 5 mixed and 117 archived messages; a read view cannot represent stable independent read watermarks/status reliably without extra durable state, and splitting parent breaks unique(account,contact) and existing references. Canonical contacts/conversations/messages stay intact. No provider second pipeline; WACRM authoritative, Meta official/default for existing contracts and OpenWA option. New Inbox never implicitly falls back.
## Entities and invariants
- Logical key (account_id, conversation_id, connection_id), opaque immutable thread id; provider derived from registry known same account and asserted against message. Composite FKs account+conversation and account+registry using live unique indices; enforce message connection and provider identity in authenticated writers/DB. Unique pair per tenant. `connection_id` non-null for valid thread; archived identity retained (no cascading history delete; parent deletion existing CRM contract handled transactionally). For missing/conflicting legacy identity, separate quarantine/legacy view keyed by parent/message (no guessed sender, no credential/native data, no send). Empty parent is explicitly unassigned history, not a connection thread. Outbound-only creates thread from explicit verified connection; no last inbound fallback.
- Fields: id/account_id/conversation_id/connection_id/provider, last_message_id/at and safe preview or join, last_trusted_inbound_at, last_trusted_inbound_message_id, ingestion cursor/highwater, unread_count_known, read_watermark, inherited legacy unread count (single scope) and unknown allocation marker, status(open/pending/closed), timestamps/version. Final SQL types/index names per INBOX-1. Persist unique ordered ingest sequence (or equivalent monotonic version + event ledger) scoped by thread; display chronological provider/created_at then id; ingestion order for read accounting so late historical delivery after read is not lost.
- Independent thread status and unread/read; CRM status/assignment/handoff/AI caps remain parent/business level. Initial thread status copied from parent as inherited snapshot (not historical assertion), inbound reopens exact thread, existing CRM behavior still runs; thread status action not silently close parent/stop tasks. Assignment remains CRM-wide, clearly labeled in UI; no duplicate assignment/triggers. CRM existing unread can be safely maintained during shadow; explicit reconciled aggregate after cutover while keeping compatibility. Notification assignment is CRM-scoped, thread notices clear only exact proven thread; legacy notice remains visible until explicit CRM read.
- All = all active connected/ready and not archived (filters separately historical/unavailable with included logged_out/archived, unknown/unassigned); no hidden mutation. Badge currently ready != eligible: policy, credential, activation, guardrail. Exact selection retains history after session disconnects. On explicit same-phone recovery authorize account+verified phone and recipient route, create/select new thread only for verified new connection; old thread remains historical; do not bind previous messages/replies to new session, no automatic switch. When reading older OpenWA without native identity no inferred JID; eligible phone only from approved verified route per existing contracts.
## Transactional maintenance
Prefer additive database-owned trigger-based projection on authoritative messages after validated insert/update/delete plus explicit server-only scoped read/status RPC (security invoker/private restricted helpers as appropriate) because writers span server/UI/API/echo/SQL. Source auth provenance is a prerequisite: current role grants/RLS allow broad writes and sender/time fields cannot individually prove trusted inbound. Establish immutable server-authored ingress provenance for signed/verified provider events; legacy inbound only if confirmed from persisted trusted evidence; unknown evidence closed Meta window. Protect provider/connection/parent/sender/time against untrusted insert/update, audit legacy caller compatibility and minimize grants, guard tenant regardless service role. Do not add public privileged bypass. No outbound provider calls/automation triggers from projection. For actual INSERT after dedup, assign scoped ingest cursor atomically, increment unread only trusted customer ingress, update preview by deterministic timestamp/id, trusted inbound max by verified provider receive timestamp; outbound/ACK status updates no unread, media hydration refresh same preview if applicable, no reordering. UPDATE identity changes prohibited except separately reviewed repair job with reconciliation; DELETE/cascade rebuild affected summary safely, no resend. Use locks/order and retry on contention; transactional row updates/rebuild batch and checkpoints. Legacy 037 conflict index retained: observed zero duplicates; test provider-identity same ID across different connection, find if old index blocks valid insertion, plan explicit additive compatibility migration before enabling if needed — never simply drop without preserving actual legacy dedup/read/reply callers.
## Historical unread and cutover
Observed 82 legacy unread: 66 single-thread parent counts and 16 across 3 mixed parents. Snapshot existing aggregate and cutover highwater in consistent transaction while source writes continue via trigger/lock. Single-thread parent count may be carried as inherited count, no claim which exact messages were read; only clear on explicit opening/mark-read of that thread through observed snapshot. Mixed parents retain unallocated legacy unread bucket (separate from known new counts, visible “legacy unread unallocated”); do not assign across sessions or silently discard. Explicit operator CRM-wide legacy acknowledgment (not provider mark read) clears only legacy bucket, audited. New post-cutover trusted inbound increments exact thread known unread; compute counts against ingest cursor. Read request includes observed cursor/version and idempotent monotonic watermark; transaction clears only inbound through observed watermark and inherited single count once; concurrent newer arrivals stay unread; do not clear other thread, hidden background scope or unknown bucket. UI reads exact visible active thread, no global reset; provider read is best-effort separate result, exact identity only with legitimate permissions. No new read behavior while flag off.
## API contract v1 (internal; final route names in INBOX-1)
All authenticated via requireRole/current account, no client account override, no credentials/private provider metadata or native chat IDs. GET /api/inbox/connections -> [{id,display_name,provider,status,archived,readiness,counts}], safe projection, counts scoped server-side; GET /api/inbox/threads?scope=active|historical|unknown&connection_id=&status=&search=&cursor=&limit= -> {items,next_cursor,counts} list keys stable and cursor bound to account/filter; GET /api/inbox/threads/{id}/messages?cursor=&limit= -> {items,next_cursor,observed_cursor,capabilities}, messages exact pair. Unknown lane read-only, no fabricated IDs. Default page 30–50, max 100 server clamp; history 50 default. Sort(last_message_at,id) and (created_at,id), keyset plus resync. Cursors validated, opaque no raw secrets. Scope filters are intersected, not client-side security. Deep links `?thread=<opaque>&connection=<uuid>`; legacy `?c=` one known thread resolves; multi prompts disambiguation; archived explicit; unknown read-only. 
POST /api/inbox/threads/{id}/read {observed_cursor,request_id}; POST existing /api/whatsapp/send with {inbox_thread_id,connection_id,conversation_id,message_type,...,idempotency_key}; validate exact scope and role before credentials and before network, recheck readiness, provider, window and guards on server; existing core only. Idempotency key bound to account/thread/action/payload fingerprint, same-key same operation result, mismatch conflict; never repeat uncertain request blindly. Use role boundaries viewer read-only, agent send/read/status, admin credential/refresh/activation. Distinguish typed not_found (tenant-safe), invalid_scope, window_expired/template_required, unsupported_capability, connection_unavailable, policy_denied/rate_limited, ambiguous_outcome; safe reasons without provider data. Reaction/reply parent must match connection and provider; unread read route no latest-other-thread. Existing API v1/MCP and legacy CRM read IDs/shapes unchanged.
## Provider policy
Capabilities derive from verified exact server connection+trusted inbound and enforce on server just before dispatch, not picker alone. Meta free-form text/media/interactive only within exact 24h window from authoritative Meta inbound on selected connection; no inbound/unknown proof = closed; approved template path if eligible, timer UTC exact expiration. OpenWA no Meta window, no Meta template/interactive/reaction currently; text/media/reply/read per supported adapter and proven scope; guardrails consent/Pilot/manual pause/rate/circuit/activation remain. Verify migration 204 in TEST and proper enforce mode before acceptance; do not bypass. AI/flow/task/broadcast context: frozen target binding/causal incoming message, keep business IDs and approvals; no silent re-route if sibling inbound. 
## Migration/recovery
1. Census all direct writers and triggers; verify source checkout and TEST ledger including dependency 204. Audit grants/provenance and clean replay; no migration rename/edit. Prepare additive projection and trigger/RPC with least privilege, feature flag server-side off, projection shadow on TEST only after authorized schema work. 
2. Restartable bounded backfill by parent/pair in consistent snapshots with durable checkpoint, no message rewrites or provider calls. Atomic live maintenance; compare counts/pairs/preview/time/unread unknown; zero unexplained mismatch, unknown documented. Existing data unchanged. 
3. New UI reads under flag with verified scope; separately gate actions until INBOX-3/5. During cutover freeze legacy UI write/read bypasses and prove auth boundaries. 
4. To roll back disable new feature; retain original records and projection for diagnosis; do not drop data, do not replay provider sends. If old writes do not maintain projection, keep flag off, rebuild from canonical rows with explicit legacy unread reconciliation before re-enable; additive forward migration for defects. Stop on cross-tenant/connection leakage, duplicate send, mismatch, missing provenance, bypass or uncertain dispatch. 
## Gate / proof
Accepted architectural choice, data contracts, read-only baseline and migration/backout strategy. No runtime or patch. SEC-INBOX-01 least privilege / trusted provenance and DEP-INBOX-01 migration parity block activation (not the design decision). Before starting implementation, close exact-ref exhaustive source census and review. Before release complete all staged tests in 08, NOTE-001 and OW-14 independent. No Production approval.
