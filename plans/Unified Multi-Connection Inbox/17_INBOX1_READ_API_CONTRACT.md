# INBOX-1 read API contract (SOF-83)

## Security and activation
All eight endpoints are authenticated GET-only and explicitly `read_only: true`. They require the current account's viewer-or-higher role, revalidate actor membership in the server-only SQL RPC, and are disabled except on the pinned TEST project with `WACRM_INBOX_READ_API=test_only`. The flag is intentionally not enabled by this work. No browser grants to any new RPC, no native IDs, provider metadata, raw receipt/lease IDs, credential data or provider token URLs. The existing legacy dashboard and API v1 are unchanged. This is not permission to send, mark-read, start a session or use a provider.

## Endpoints
| GET path | Query | Meaning |
|---|---|---|
| /api/inbox/channels | scope=active (default), historical, all; channel_id; limit; cursor | unique verified logical channels, provider, own verified OpenWA phone where available, display name, ready/primary and known unread |
| /api/inbox/connections | scope=active (default), historical, unknown, all; channel_id; limit; cursor | safe registry and session diagnostics; registry_online is transport status, ready is exact current verified membership; historical epoch never usable |
| /api/inbox/threads | scope=active (default), historical, unknown; channel_id; status; search; limit; cursor | one row per verified channel/CRM parent; unknown rows refer to original CRM parent, not an invented channel/thread |
| /api/inbox/threads/{threadId}/messages | scope=active (default) or historical; channel_id; limit; cursor | exact thread history; origin connection internal UUID, same-thread reply, safe account-owned media only |
| /api/inbox/unknown/{conversationId}/messages | scope=unknown (default); limit; cursor | unassociated source rows only; no sender eligibility, no cross-lane quoted message IDs |
| /api/inbox/threads/{threadId}/messages/{messageId}/observations | scope=active (default) or historical; channel_id; limit; cursor | exact message/thread observation diagnostics; connection internal UUID, display label, direction, observation time |
| /api/inbox/counts | scope=all (default), active, historical, unknown; channel_id; status; search | selected lane threads, known unread, lane_messages; global source/associated/unresolved and legacy_crm_unread |
| /api/inbox/resolve/{conversationId} | scope=all; connection_id; limit; cursor | paginated candidates for legacy links, including ambiguous or historical membership; no implicit sender |

Page response: `{ items, next_cursor, read_only: true }`. Thread history adds `scope, channel_id, conversation_id, observed_highwater, read_watermark`; highwater, watermark and ingest_sequence are decimal strings for precision. Unknown has null channel and watermark. Counts response `{ counts, read_only: true }`. Default limit 30 (history 50), valid 1–100. Strict unknown/duplicate parameter and invalid cursor errors are 400; missing or foreign resource is 404; unauthenticated 401, forbidden or flag off 403, sanitized internal failure 500. Cache-Control: private, no-store. UUID and timestamp validated; domain-separated signed cursor binds account, user, endpoint, scope, all filters and limit; preserves timestamp microseconds and deterministic NULLS LAST + UUID ordering. New activity can reorder threads between requests; resync first page on realtime or scope changes; no cross-request snapshot or write authorization implied. Channel scope change rejects stale history cursor rather than exposing another lane.

## Conserved data semantics
The active/historical partition depends on an exact online verified membership; current registry phone strings do not create a channel. The same verified number on multiple OpenWA sessions maps to one thread and logical unread; Meta and distinct verified numbers stay independent. History includes old membership epochs, even when a session is archived or re-paired. Unknown remains a separate read-only parent lane. It includes unassociated messages, empty parents and unresolved legacy CRM unread; it never silently adopts them into a provider. Legacy CRM unread is a non-additive shadow value (may overlap known unread), not a guessed channel count. No provider action or backfill invoked by reads. Counts distinguish actual lane messages from global source conservation. No raw native observations are combined into a second copy of the message. Media references are limited to exact TEST project public Storage paths for the authorized account; unsupported/foreign/external URLs are omitted, with has_media retained. Full action authorization, read watermarks mutation, realtime/UI and live verification remain later phases.

## Verification
Run `supabase/ci/inbox-read-api-smoke.sql` against applied schema in a rollback transaction and `16_INBOX1_TEST_READ_CONSERVATION.sql` on TEST only. The latter scans all source rows through bounded pages with duplicate and omission assertions; no source write or provider call. The large-scale latency budget remains INBOX-5, not established by the small TEST sample.
