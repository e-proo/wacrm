# SOF-64 — اختيار جلسة WhatsApp على مستوى المهمة

**Scope:** `SOF-23` Phase 18 TEST readiness. لا يشمل تغيير مفتاح مزوّد الذكاء الاصطناعي أو إعدادات الوكيل العامة.

## واجهة المستخدم

- تبويب `Agents → مهام الوكلاء` يحمّل الجلسات مباشرة من `whatsapp_connections` ضمن الحساب الإداري الحالي، دون إظهار المفاتيح أو رابط OpenWA.
- تختار مهمة Coverage وكيلًا له نسخة منشورة، وCoverage Request مؤهلًا، والاتصال `meta_cloud` أو `openwa` أو خيار «اتصال آخر رسالة واردة» **صراحةً**.
- الخيارات غير الجاهزة والمؤرشفة معطّلة؛ لا يوجد Meta fallback عند غياب اتصال OpenWA. تظهر الجلسات الجديدة بعد تحديث القائمة.
- إنشاء المهمة يستخدم الدالة الموجودة `startCoverageSourcingTask`، والتحقق من حدود Builder والنسخة المنشورة وسياسات المهمة؛ لا يوجد Task Pipeline موازٍ.
- تعديل جلسة المهمة وحدودها فقط إن كانت `queued` أو `scheduled` ولم تُنشأ Targets/Runs/Reservations؛ يتم ذلك في SQL مقفل بالصف، وبصلاحية admin/owner، ودون رفع سقوف الأرقام. لا يمكن تعديل جلسة رسالة محجوزة.
- عند إغلاق بوابة `outbound_task_delivery_enabled` يبقى زر الإنشاء غير متاح، ولا يحدث إرسال. الشاشة تعرض السبب بوضوح.

## اختبارات SOF-62

- تحقّق من صلاحيات `agents.manage_tasks` في كل API.
- API يتجاهل IDs الحساب/المستخدم المرسلة من العميل ويستخدم السياق المصادق عليه.
- Migration `160_agent_task_pending_connection_edit.sql`: حماية tenant/admin، منع اتصال حساب آخر، منع زيادة السقوف والتعديل بعد البدء، صلاحية الدالة service-role فقط.
- اختبارات Coverage V1 Meta وV2 provider-aware، وعمليات الحجز القفلية؛ `Supabase CI` replay من قاعدة نظيفة، `lint/typecheck/tests/build` على آخر HEAD.
- لا تُختبر الرسائل الحية إلا ضمن SOF-63 مع جلسة OpenWA جاهزة، رقم موافق تجريبي، موافقة Pilot وrollback.

## حدود حالية

واجهة إنشاء المهام تبدأ بـCoverage ضمن Phase 18، مع قابلية توسيع نفس النمط إلى Service Promotion عندما تُعتمد سياسة مزودها. إنشاء مهام فعلية يبقى محظورًا عندما تكون بوابة الإرسال مغلقة.
