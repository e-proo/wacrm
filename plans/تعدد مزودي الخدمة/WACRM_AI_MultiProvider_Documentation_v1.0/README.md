# حزمة توثيق تعدد مزوّدي الذكاء الاصطناعي في WACRM

**الإصدار:** 1.0  
**تاريخ الإعداد:** 2026-09-03  
**حالة الوثيقة:** جاهزة للتخطيط والتنفيذ المرحلي  
**الجمهور:** مالك المنتج، المعماري، مطوّر WACRM، مراجع الأمن، ومهندس الاختبارات

## لماذا قُسّمت الحزمة؟

قُسّمت الوثائق بدلاً من وضع كل شيء في برومبت ضخم فقط، لأن المشروع يجمع بين متطلبات منتج، وتصميم معماري، وترحيل قاعدة بيانات، وأمن اتصالات خارجية، وتجربة مستخدم، واختبارات. جمع هذه الطبقات في برومبت واحد يجعل التنفيذ أصعب والمراجعة أقل دقة.

مع ذلك، توجد وثيقة رئيسية جامعة يمكن قراءتها أو تسليمها كما هي، إضافة إلى برومبتات قصيرة مستقلة لكل مرحلة. هذا يحقق فائدتين:

1. مرجع واحد يمنع ضياع الصورة الكاملة.
2. مهام مرحلية صغيرة تمنع الذكاء الاصطناعي البرمجي من إجراء تعديل واسع وغير مضبوط.

## ترتيب السلطة عند التعارض

عند وجود تعارض، يُتبع الترتيب التالي:

1. حالة المستودع الفعلية وتعليماته المحلية مثل `AGENTS.md` و`CLAUDE.md`.
2. المتطلبات الأمنية ومعايير عدم فقد البيانات الواردة في الوثيقة الرئيسية.
3. القرارات المعمارية المسجلة في `architecture/DECISIONS.md`.
4. خطة الطريق والبرومبت المرحلي.
5. أمثلة أسماء الملفات والأنواع، فهي قابلة للتكييف مع بنية الفرع الفعلي.

## طريقة الاستخدام الموصى بها

1. ضع الحزمة تحت `docs/ai-multi-provider/` في فرع عمل منفصل، أو احتفظ بها كمرجع خارجي.
2. سلّم برومبت المرحلة صفر إلى وكيل البرمجة أولاً.
3. قارن تقرير الاستكشاف مع «خط الأساس المرجعي» في الوثيقة الرئيسية؛ لا تفترض أن الفرع مطابق له.
4. نفّذ مرحلة واحدة فقط في كل دورة مراجعة.
5. لا تنتقل إلى المرحلة التالية قبل اجتياز بوابة المرحلة وكتابة تقريرها.
6. سجّل أي انحراف جوهري عن هذه المواصفات في ADR واضح قبل التنفيذ.

## حدود هذا التوثيق

هذه الحزمة لا تنفّذ التغييرات، ولا تفترض امتلاك مفاتيح حقيقية، ولا تمنح إذناً بالنشر أو تشغيل ترحيل إنتاجي أو استهلاك مدفوع. هدفها تحويل الفكرة إلى مواصفات قابلة للتنفيذ والمراجعة والاختبار بأمان.
